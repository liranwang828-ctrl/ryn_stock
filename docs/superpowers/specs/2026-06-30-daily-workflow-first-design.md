# 日常交易工作流优先设计

## 目标

先让系统以最小能力完整走通并可恢复日常工作流，再根据真实阻塞安排局部任务。当前阶段不追求单个模块完善，也不对 `stock_team` 做全仓重构或全面考古。

## 核心约束

- 项目级名称、边界与工作流目录以 `investing-os/PROJECT-CHARTER.zh.md` 为准。
- 每日流程统一命名为 `DAILY-0` 至 `DAILY-4`：晨间准备、盘前决策、开盘观察、盘中管理、盘后复盘。
- 原 Evidence Stage 0/1 是 `DAILY-1` 内部的市场环境证据包和焦点标的证据包，不是完整每日步骤。
- 旧 Node 0/1/2/3/6 只作为历史实现映射，不再作为新文档和界面的主名称。
- 首轮目标是验证流程、固定产物、中断恢复和每日操作，不是提高每一步的深度。
- 模拟数据必须明确标记，不得冒充真实盘前、持仓或交易数据。
- IBKR 仍是正式持仓与交易记录的唯一来源。
- 不扫描整个 `stock_team`。只审计完整流程实际触及的能力。

## 最小完整闭环

```text
DAILY-0 晨间准备
→ DAILY-1 盘前决策
→ DAILY-2 开盘观察
→ DAILY-3 盘中管理
→ DAILY-4 盘后复盘
```

每个步骤在首轮只需满足：

1. 有明确入口和完成条件。
2. 有固定路径、固定 schema 的输入输出或状态记录。
3. 能显示当前步骤、缺失项和下一步。
4. 失败后保留原因，并允许从已完成节点恢复。
5. 模拟模式与真实模式可辨认。

除非阻断完整闭环，首轮不处理数据覆盖率、界面精修、算法增强、旧脚本归档或模块内部重构。

## 推进方式

### 1. 固定协作护栏

先建立精简任务单、执行日志和审核记录模板。模板约束低阶模型的读取范围、修改范围、输入输出契约、验收命令和停止条件。

### 2. 骨架级全链模拟

使用明确标记的非交易模拟输入，依次经过 `DAILY-0` 至 `DAILY-4`。每个故障先登记，不自动展开深挖。

只有以下问题可以在本轮立即修复：

- 阻断流程进入下一节点；
- 导致已完成状态丢失或无法恢复；
- 混淆模拟数据与真实数据；
- 违反 IBKR、证据包依赖、DAILY 顺序、权限或用户确认边界。

其余问题进入任务候选清单。

### 3. 固定每日操作清单

根据模拟结果形成面向用户的每日清单，说明：

- 今天从哪里开始或恢复；
- 当前需要用户确认什么；
- 系统应生成什么固定产物；
- 某一步失败时如何继续；
- 如何完成收尾并确认当日结束。

### 4. 建立最小能力地图

只记录模拟流程实际触及的 `stock_team` 能力：

```text
能力名称
流程位置
当前入口
数据来源
固定产物
验证证据
已知缺口
处理结论
```

处理结论只能是：

- `active`：主链正在使用且已验证；
- `reuse`：旧实现值得局部复用或提取；
- `reference`：仅供理解和借鉴，不进入运行时；
- `retire-candidate`：疑似重复或失效，暂不删除。

### 5. 按阻塞安排任务

任务按以下顺序进入实施：

1. P0：主链不能继续、不能结束或不能恢复；
2. P1：数据真实性、账户来源、DAILY 顺序、证据包依赖、权限或确认边界错误；
3. P2：用户不知道每天该做什么，或固定产物不可验证；
4. P3：体验、覆盖率、算法增强和旧代码整理。

每完成一个任务，都重新运行最小全链回归。局部测试通过但完整流程退化，不算完成。

## 高低阶模型协作

### 高阶模型

- 维护 DAILY、Evidence Packet、状态机、权限和数据真实性契约；
- 从模拟记录中选择下一项任务并控制优先级；
- 编写有边界的任务单；
- 审核 diff、测试、交付日志和全链回归；
- 决定旧能力是复用、参考还是保留为退役候选。

### 低阶模型

- 一次只执行一个任务单；
- 先写或更新测试，再做最小实现；
- 只修改任务单允许的文件；
- 记录验证结果、风险、未解决问题、commit 和 push；
- 遇到契约冲突、DAILY 步骤或证据包语义不明、数据来源不明时停止局部工作并上报。

低阶模型不得自行：

- 改变 DAILY 步骤、Evidence Packet 依赖或状态转换；
- 改变 IBKR 的正式来源地位；
- 把模拟输入标记为真实数据；
- 扩大任务范围去整理相邻旧代码；
- 删除或迁移退役候选文件。

## 单任务交付节奏

```text
高阶模型从阻塞清单选择一项
→ 写任务单
→ 低阶模型测试驱动实现
→ 低阶模型提交交付日志与独立 commit
→ 高阶模型审查契约和改动
→ 运行局部测试与最小全链回归
→ 审核通过后 push
→ 更新能力地图和阻塞清单
```

每个任务只解决一个可观察缺口，不以“彻底做好某模块”为目标。

## 第一阶段完成标准

- 非交易模拟能够依次经过 `DAILY-0` 至 `DAILY-4`；
- 任意节点中断后能够显示并恢复到正确位置；
- 用户能通过每日操作清单知道当前要做什么；
- 每个节点的固定产物和缺失项可见；
- 模拟数据与正式来源不会混淆；
- 流程触及的能力已进入最小能力地图；
- 发现的问题已按 P0 至 P3 排序，并能转换成独立任务单；
- 不依赖全仓扫描或先完成旧代码清理。

## 暂不包含

- 全面盘点、移动或删除 `stock_team` 历史文件；
- 完善全部行情、研究或 Agent 能力；
- 重做 Dashboard 视觉设计；
- 自动替用户作出交易决定；
- 在流程验证前优化单个 DAILY 步骤的所有细节。
