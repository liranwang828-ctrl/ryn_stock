# 高低阶模型协同协议

更新日期：2026-06-01

## 1. 目标

本协议用于最大化高阶模型的使用效率：高阶模型负责判断、拆解、关键实现和验收；低阶模型负责低风险、高耗时、可复核的辅助任务。

低阶模型的工作不能直接影响交易系统完成度。任何会改变交易判断、系统规则、资金状态、真实持仓或核心执行链路的内容，都必须由高阶模型亲自完成或最终复核后合入。

## 2. 角色分工

### 高阶模型职责

- 设计系统边界、任务优先级和交付标准。
- 判断交易规则、回测可信度、因子可信度、LLM 主控纪律。
- 修改核心代码、交易流程、回测逻辑、真实配置。
- 给低阶模型写明确委托单。
- 审查低阶模型产出，决定是否采纳、修改或丢弃。
- 运行测试、检查 diff、做最终交付说明。

### 低阶模型职责

- 执行明确、低风险、可验收的任务。
- 整理文档、摘录字段、生成表格、做重复信息归并。
- 阅读日志或 JSON 后输出摘要。
- 准备 dashboard / 可视化 agent 所需字段说明。
- 草拟非核心测试、样例数据或迁移清单。
- 遇到不确定内容时标记“待高阶模型确认”，不得自行补交易结论。

## 3. 任务分级

### A 级：高阶模型专属

低阶模型禁止执行。

- 改交易规则、止损规则、仓位规则、入场/出场门槛。
- 改 `agents/backtest_*`、`scripts/weekly_*`、因子计算核心、LLM 主控核心。
- 改 `config/positions.json`、真实持仓、交易历史、API key、`.env`。
- 删除文件、清理 git、改 `.gitignore` 中涉及数据保留的规则。
- 直接给交易建议、提升置信度、把 caution 包装成 strong signal。
- 修改 `decision_state_hub.py`、`premarket_decision.py` 等主控链路，除非高阶模型先给出逐项 patch plan 并最终复核。

### B 级：可委托，但必须复核

低阶模型可以做草稿或局部改动，高阶模型必须审查后才算完成。

- 文档补充、中文翻译、runbook 初稿。
- TODO 整理和归类。
- 测试草稿、fixture 草稿、字段 schema 草案。
- 从 JSON / 日志 / 报告中提取摘要。
- dashboard 字段说明、界面信息架构建议。
- 非关键脚本的只读检查、文件清单、重复项扫描。

### C 级：可独立完成

低阶模型可以直接完成，但仍需在交付中列出改动。

- Markdown 格式整理。
- 表格排版。
- 文件索引和链接清单。
- 中文摘要和英文简版互译。
- 无判断性的字段复制、路径列表、命令输出摘要。

## 4. 委托单格式

高阶模型给低阶模型任务时，必须使用以下格式：

```text
任务等级：B / C
目标：
输入文件：
允许修改：
禁止触碰：
输出位置：
输出格式：
验收标准：
不确定时：
```

示例：

```text
任务等级：B
目标：整理今天盘前流程暴露的问题，形成 TODO 草稿。
输入文件：
- docs/premarket_planning_runbook_2026-06-01_zh.md
- findings/decision_state_2026-06-01.json
允许修改：
- docs/premarket_workflow_todo_2026-06-01_zh.md
禁止触碰：
- agents/
- config/
- findings/entry_decision_*.json
- findings/exit_decision_*.json
输出格式：中文优先，分 P0/P1/P2。
验收标准：只记录流程问题，不提出交易建议，不改交易规则。
不确定时：写“待高阶模型确认”。
```

## 5. 低阶模型输出要求

低阶模型每次交付必须包含：

1. 改了哪些文件。
2. 使用了哪些输入。
3. 哪些地方不确定。
4. 是否触碰了禁止文件。
5. 建议高阶模型重点复核什么。

低阶模型不得使用“已完成”“已验证”“可以交易”等最终性措辞，除非高阶模型已验收。

## 6. 高阶模型验收清单

接收低阶模型产出后，高阶模型必须至少检查：

```powershell
git status --short
git diff --stat
```

如果涉及代码：

```powershell
python -m py_compile <changed python files>
python -m pytest <focused tests> -q
```

如果涉及盘前流程：

```text
确认 decision_state_{date}.json 中所有目标标的：
- premarket_summary.status = fresh
- entry_decision.status = fresh
- controller.audit.allowed_actions 未被绕过
```

如果涉及文档：

- 中文优先。
- 没有把待办写成已完成。
- 没有把交易建议混进流程文档。
- 没有新增与现有 runbook 冲突的规则。

## 7. 禁止协同模式

以下模式禁止：

- 把模糊目标直接丢给低阶模型，让它自行决定系统方向。
- 让低阶模型边读边改核心代码。
- 让低阶模型直接清理脏工作区。
- 让低阶模型修改真实持仓或交易配置。
- 让低阶模型对实时行情做最终解释。
- 高阶模型不看 diff 就接受低阶模型结果。

## 8. 推荐协同模式

推荐流程：

```text
高阶模型拆任务
→ 写委托单
→ 低阶模型产出草稿或低风险改动
→ 高阶模型检查 diff / 测试 / 逻辑
→ 高阶模型决定合入、修正或丢弃
→ 高阶模型向用户汇报最终状态
```

## 9. 当前系统中的优先委托场景

适合交给低阶模型：

- 将英文设计文档补一份中文版。
- 把 TODO 按 P0/P1/P2 归档。
- 从 `decision_state_{date}.json` 提取 dashboard 字段说明。
- 汇总 runbook 的命令清单。
- 检查哪些文档还缺中文摘要。
- 整理回测报告中的字段定义，不判断交易含义。

不适合交给低阶模型：

- 解释今天是否应该买入/卖出。
- 修改入场否决逻辑。
- 判断因子是否足够可信。
- 重跑或修改完整回测。
- 设计新的仓位规则。
- 修复 API 数据源优先级代码。

## 10. 最终原则

低阶模型是“节省阅读和整理成本”的助手，不是系统决策者。它可以帮忙把桌面收拾好、把材料排整齐、把重复劳动做完；但门该不该开、钱该不该动、规则该不该改，必须由高阶模型和用户共同确认。
