# RynStock 量化执行引擎物理结构与目录边界指南

本指南定义了 `stock_team`（量化执行层/“肌肉”）的目录树结构、各个子文件夹的单一职责与边界，旨在将该项目从散乱的脚本和缓存，提纯为一个干净、无状态的**“数据/事实证据发动机 (Evidence Engine)”**。

---

## 1. 系统物理结构树状图

```text
stock_team/
+-- .env                      # 敏感密钥配置（已在 Git 中忽略，严禁复制到 Brain 侧）
+-- .env.template             # 环境变量配置模板
+-- README.md                 # 仓库总览
+-- CLAUDE.md                 # 脚本调用契约与大师角色扮演规则
+-- main.py                   # 执行层统筹运行入口
+-- morning.py                # 晨间Node 0 自动编排脚本入口
+-- agents/                   # 量化决策计算与盘中轮询逻辑
+-- config/                   # 集中化量化配置与运行规则快照
+-- docs/                     # 系统流程、协议规范与物理指南
+-- findings/                 # 活跃会话状态、当前指标及已导出事实包
+-- knowledge/                # 运行时系统数据库与知识快照
+-- learning/                 # 大师准确度追踪、历史特征及后验对齐日志
+-- scratch/                  # 一次性快速诊断的临时沙盒空间
+-- scripts/                  # 官方命令行工具、数据包导出器与回测器
+-- tests/                    # 自动化测试套件
+-- archive/                  # 历史归档保险库（session/scratch/认知资产）
```

## 2. 目录详细定义与边界规范

### 🟢 `agents/` (量化计算层)
*   **职责**：包含所有技术面（TechAgent）、基本面（FundAgent）、宏观（MacroAgent）、风险（RiskAgent）等量化计算模块，以及 `poll.py` 盘中轮询逻辑和 `session_manager.py` 工作流。
*   **边界**：仅做无状态的数学指标计算与评分输出，禁止在其中硬编码主观投资逻辑或交易决策。

### 🟢 `config/` (量化参数配置)
*   **职责**：存放核心交易账户配置 (`accounts.json`)、杠杆配置、静态观察池等。接下来将作为 `tactical_rules.json`（定量参数快照）的唯一存放地。
*   **边界**：本目录不应存在定性纪律，只承载由 `investing-os` 导出的定量数值。

### 🟢 `docs/` (设计与规范)
*   **职责**：存放系统数据流图、开发指南、未来路线图及本结构说明书。
*   **边界**：所有文档均围绕 `stock_team` 的工程实现展开。

### 🟢 `findings/` (事实/证据输出层 - 核心契约)
*   **职责**：存放当前交易日的实时指标快照（如 `watchlist_live_status.json`）和导出的只读 Markdown 事实证据包（如 `contextual-trade-evidence-*.md`）。
*   **边界**：这是 `stock_team` 向 `investing-os` 提供物理证据的唯一出口。里面的数据包必须是“纯事实与计算”，严禁带有交易建议或主观反思。

### 🟢 `knowledge/` 与 `learning/` (历史与反馈环)
*   **职责**：`knowledge/` 存放运行快照；`learning/` 存放每日收盘后将预设信号与真实收盘对齐的 `observation_outcomes.jsonl`，用于追踪大师预判的物理胜率。
*   **边界**：只记录物理计算所得的胜率、特征或偏离度，不承载交易心理或反思。

### 🟢 `scripts/` (官方命令行工具)
*   **职责**：存放导出器、数据刷新器及战术回测引擎等官方 CLI 执行工具。
*   **边界**：所有的脚本必须提供干净的 CLI 参数输入，并在失败时输出完整的数据完备度说明（`missing-data`）与失败 diagnostics。

### 🟢 `tests/` (质量防御层)
*   **职责**：存放单元测试和集成测试。
*   **边界**：测试代码将重构并分层，防止测试套件退化。

### 🟢 `archive/` (历史保险 vault)
*   **职责**：
    *   `session_history_2026-06/`：存放 6 月以前的大量平铺缓存。
    *   `scratch_history/`：大清理移入的 130 个临时调试和文本输出。
    *   `cognitive_assets/`：已妥善保护的 18 个高价值认知文档，随时等待主脑 `investing-os` 在合适的时候只读复制并重写吸收到 Wiki 中。
*   **边界**：此目录只做安全存档，运行时代码绝不读取其中的内容。
