# 美股交易日归属与会话选择设计

## 目的

消除北京时间跨日导致的 DAILY 会话切换错误，并防止历史交易日产物被 Dashboard 误报为当前交易日已就绪。

本设计只规范交易日、会话选择和产物新鲜度。它不改变 DAILY-0 至 DAILY-4 的业务内容，也不把流程判断迁入 Dashboard。

## 已确认原则

1. `trading_date` 是唯一业务日期，按 `America/New_York` 和美股交易所日历确定。
2. 北京时间只用于界面显示和操作日志，不参与 session、产物或归档归属。
3. 同一美东交易日的盘前、盘中、盘后和复盘，即使跨过北京时间零点，仍属于同一个 `trading_date`。
4. Dashboard 只展示轻量检查器的结果，不自行推断复杂工作流状态。
5. 历史产物可以保持“结构有效”，但不得因此被标记为当前交易日“新鲜”或“就绪”。

## 方案选择

### 采用方案：集中式交易日上下文

新增一个小型、无副作用的交易日上下文组件，统一输出：

- 当前美东时间；
- 当前或最近的交易所交易日；
- 当前是否属于正式交易日；
- 当前会话应当匹配的 `trading_date`；
- 北京时间显示值。

`daily_status`、会话选择和 Dashboard 初始化均消费该组件，不再各自调用本机 `date.today()`。

### 未采用方案

- 只把服务器时区改成美东：无法正确处理周末和交易所节假日，也会留下分散判断。
- 只比较文件修改时间：修改时间不代表产物所属交易日，复制或重写文件会造成假新鲜。

## 交易日语义

### 正式交易日

交易所日历确认开放的日期才可成为正式 `trading_date`。当美东仍处于该日的盘前、正常交易时段、盘后或该日尚未归档的复盘阶段，所有操作继续挂在该日会话下。

例如，北京时间次日 03:00 可能仍是美东前一日 15:00；系统必须继续使用前一美东日期，不能按北京时间创建新会话。

### 非交易日与闭市间隔

周末和交易所节假日不自动创建正式交易会话。Dashboard 应区分：

- `active_trading_date`：当前正在处理且尚未终结的正式交易会话；
- `last_trading_date`：最近一个已经发生的交易日；
- `next_trading_date`：下一个可交易日期，仅用于提示，不能提前生成正式会话。

非交易日可以进入研究或观察界面，但不能把研究日期伪装成正式 `trading_date`。

### 盘后与归档

盘后复盘继续归属当日 `trading_date`，直到明确归档。北京时间跨日不触发自动归档，也不把未完成会话静默替换为下一交易日。

## 会话选择规则

选择顺序固定为：

1. 若存在唯一未终结的正式会话，先判断它是否需要恢复；
2. 若其 `trading_date` 等于交易日上下文的当前交易日，作为当前会话；
3. 若其日期较旧，显示“历史会话待恢复/收尾”，不得把产物放进今天的就绪统计；
4. 若存在多个未终结旧会话，阻断自动选择并进入诊断；
5. 若没有未终结会话且当前是正式交易日，才允许初始化该交易日会话；
6. 若当前不是正式交易日，不自动创建未来交易日会话。

“最新修改的 session 文件”不能单独决定当前会话。

## 产物有效性与新鲜度

产物状态拆成两个独立维度：

- `validity`：文件存在、可解析、满足 schema 和业务字段要求；
- `freshness`：产物声明的 `trading_date` 是否匹配当前所检查的正式会话，并满足该产物自身的时间窗口要求。

规则如下：

- `valid` 不自动等于 `fresh`；
- `artifact.trading_date != selected_session.trading_date` 时必须为 `stale`；
- 历史 session 的产物可显示 `valid + historical`，但不能计入当前交易日 readiness；
- 新鲜度不得只依赖文件修改时间；
- 缺少可验证日期的旧产物标记为 `unverified`，不能自动授予流程推进资格。

## Dashboard 展示

页面头部同时显示：

- `交易日：YYYY-MM-DD ET`；
- `北京时间：YYYY-MM-DD HH:mm`；
- 会话性质：当前、待恢复、历史或非交易日。

如果没有当前交易日会话，首页明确显示“今日尚未开始”。历史产物只出现在恢复、历史或诊断区域，不得在 Evidence 页显示为今日已就绪。

Dashboard 不自行重新计算交易日，只展示后端返回的交易日上下文和 DAILY 状态 manifest。

## 失败与降级

- 交易所日历不可用时，系统进入 `calendar_unverified`，不得仅凭本机日期创建正式会话。
- 时区转换失败时，阻断正式会话初始化并给出诊断信息。
- 产物日期字段缺失或冲突时，标记为 `unverified` 或 `stale`，不静默修正文件。
- 旧会话损坏或多个未终结会话并存时，沿用现有恢复阻断机制。

## 最小实施边界

第一轮只做：

1. 提供统一交易日上下文；
2. 修正 DAILY 状态中的有效性/新鲜度分离；
3. 修正 operating console 的会话选择和双时区显示；
4. 增加北京时间跨日、周末/节假日、旧产物和旧会话的回归测试；
5. 用隔离 runtime 重跑 DAILY-0/1，不修改真实账户或交易权限。

暂不处理 IBKR streaming、完整盘中监控、认知成长算法或旧文件清理。

## 验收标准

1. 北京时间跨过零点但美东仍为同一交易日时，session 不切换。
2. 周末或交易所节假日不创建正式 DAILY session。
3. 旧 session 的有效产物显示为历史或 stale，不计入今日 readiness。
4. 当前交易日产物只有在日期匹配且满足产物规则时才显示 fresh。
5. Dashboard 同时显示 ET 交易日和北京时间，并能明确区分今日未开始与旧会话待恢复。
6. 隔离 DAILY-0/1 试跑不读取旧日期产物作为当前证据。
