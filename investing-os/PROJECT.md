# Project Management

Version: 1.0

## Project Identity

`investing-os` is the cognition, discipline, AI-agent, workflow, and knowledge layer for personal investing.

It exists to serve the purpose defined in `WHY.md`:

- Cognition is the engine.
- AI is the amplifier.
- Discipline is the moat.
- Review is the evolution mechanism.
- Long-termism is the direction.
- Returns are a byproduct.

## Non-Goals

This project is not:

- An automatic trading bot
- A quant backtesting engine
- A raw data warehouse
- A signal-chasing dashboard
- A place to outsource final judgment to AI

## What Belongs Here

Content may enter this project if it improves at least one of:

- Cognitive evolution
- Research quality
- Discipline execution
- Risk control
- Falsification
- Review and learning
- Agent reliability
- Long-term knowledge accumulation

## What Does Not Belong Here

Keep these outside the core project:

- Raw market data
- Large exports
- Experimental scripts without durable lessons
- One-off trade ideas without thesis
- Strategy code that belongs in a separate quant project
- Anything designed mainly to increase trading frequency

## Relationship With External Projects

External projects may act as labs, tools, or data sources.

`investing-os` absorbs:

- Lessons
- Validated methods
- Research conclusions
- Failure patterns
- Workflow improvements
- Risk rules

`investing-os` should not absorb:

- Raw experiments
- Temporary notebooks
- Large datasets
- Backtesting engines
- Strategy implementation code

## Entry Rule

Before adding a significant file, workflow, agent, or integration, run the WHY Alignment Check:

1. Does this serve cognitive evolution?
2. Does this keep final judgment human-owned?
3. Does this improve discipline?
4. Does this reduce emotional decision-making?
5. Does this include falsification where needed?
6. Does this respect risk first?
7. Does this create durable knowledge rather than temporary noise?

If the answer is unclear, put the item in a research queue instead of adding it to the core.

## Project Rhythm

Daily:

- Pre-market plan after work
- Sleep-before-risk check
- Asynchronous review after waking or during available daytime
- Company scan or research when time allows

Weekly:

- Review trades, emotions, mistakes, and thesis changes
- Update wiki and watchlist
- Choose next research focus

Monthly:

- Review framework drift
- Improve templates and agents
- Reassess information sources

Quarterly:

- Review constitution-level beliefs
- Check whether the system still serves `WHY.md`

## Governance Rule

When in doubt, prefer:

- Fewer trades
- Better notes
- Clearer falsification
- Smaller risk
- Stronger review
- More durable cognition
