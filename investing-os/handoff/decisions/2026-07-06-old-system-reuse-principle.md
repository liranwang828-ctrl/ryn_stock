# 旧系统复用原则确认

日期：2026-07-06

## 决策

用户确认：

> `investing-os` 旧系统资产默认按“直接全部复用”处理。

这意味着：

1. `investing-os` 不再被视为“参考素材库”或“可选灵感来源”。
2. 旧 `investing-os` 中已经存在的主脑资产，默认视为 canonical。
3. 新工作应优先：
   - 恢复旧 `investing-os` 资产的正式地位；
   - 让当前 DAILY / dashboard / cognition 链路重新接回这些资产；
   - 仅在出现明确冲突、断裂或无法运行时，才做必要适配。

## 边界说明

本决策主要约束 `investing-os`。

对 `stock_team` 的处理口径不同：

- `stock_team` 中属于事实获取、运行时承接、旧 dashboard server / writer / template 的部分，
  仍需区分：
  - 可直接沿用；
  - 需要接管式重构；
  - 仅保留为历史参考。

原因：

- `investing-os` 是主脑，旧系统内容本就属于主系统本体；
- `stock_team` 是肌肉，部分旧运行面存在膨胀、混杂和职责漂移，需要继续审计后决定是否原样沿用。

## 对后续工作的直接影响

从本记录开始，后续规划与实现默认遵循以下顺序：

1. 先找旧 `investing-os` 中是否已有对应资产；
2. 若已有，优先复用或恢复其 canonical 地位；
3. 若旧资产与当前链路冲突，再记录冲突点并做最小必要适配；
4. 不再默认从零重写 `investing-os` 对应能力。
